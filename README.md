# RJA-Peaks · 北京周边山峰多库综合地图

一个基于 MapTiler SDK 的交互式山峰地形显著度地图，整合了北京及周边多个区域的山峰数据库，支持按高差、突起度（Jut）、地形锐度（ATS）与全向高差-坡度指标（ORS）等多维指标进行可视化、筛选与对比。

**在线访问：** [https://Survinian.github.io/RJA-Peaks/](https://Survinian.github.io/RJA-Peaks/)

---

## 项目概述

本项目试图在传统海拔、地形突起度、孤立度之外，进一步描述“山峰看起来是否真正震撼”这一问题。为此，项目同时保留了：

- **高差（Relief）**：反映局部起伏强度
- **Jut**：同时考虑高差与仰角的视觉压迫感指标
- **ATS**：由 Jut 与高差共同构成的综合锐度指标
- **ORS**：来自山峰周边全方向积分思想的综合陡峻度指标

其中，Relief / Jut / ATS 采用完整多半径剖面计算；ORS 在理论上源于连续平面上的全方向积分，但考虑到前端交互和大规模区域批量计算的现实约束，本项目在 GEE 的 `.js` 计算脚本中采用了若干工程化简化策略，以获得可运行、可批量导出、可前端实时调用的近似结果。

## 指标体系

所有指标在多个采样半径（125 m–10,000 m）下独立计算，形成完整的多尺度剖面。

### 第一阶：基础起伏场

**高差（Relief）**

$$R_{mean}(r) = \frac{1}{N_r} \sum_{i \in D_r}(Z_{peak} - Z_i)$$

$$R_{max}(r) = \max_{i \in D_r}(Z_{peak} - Z_i)$$

**突起度（Jut）**：高差与仰角的乘积，保留负值以惩罚卫峰和台地

$$J_{mean}(r) = \frac{1}{N_r} \sum_{i \in D_r} \frac{(Z_{peak}-Z_i)\cdot|Z_{peak}-Z_i|}{\sqrt{(Z_{peak}-Z_i)^2+d_i^2}}$$

$$J_{max}(r) = \max_{i \in D_r} \frac{(Z_{peak}-Z_i)\cdot|Z_{peak}-Z_i|}{\sqrt{(Z_{peak}-Z_i)^2+d_i^2}}$$

### 第二阶：无量纲形态因子

| 指标 | 公式 | 物理意义 |
|------|------|---------|
| 极限绝壁度 CI | $J_{max} / R_{max}$ | 最陡剖面的 sin(θ)，越接近 1 越像垂直断崖 |
| 全局陡峭度 GS | $J_{mean} / R_{max}$ | 满视野平均压迫感占极限高差的比例 |
| 山体纤细度 SL | $R_{mean} / R_{max}$ | 山体骨感程度，接近 1 为细针，接近 0 为平顶高原 |
| 尖锥各向同性 SF | $J_{mean} / J_{max}$ | 险峻是否全方位，接近 1 为孤立尖锥，接近 0 为单面绝壁 |

### 第三阶：综合地形锐度

**纯形态锐度指数（FSI）**

$$FSI(r) = \frac{J_{mean}(r) \cdot R_{mean}(r)}{[R_{max}(r)]^2}$$

**绝对地形锐度（ATS）**：本体系核心指标，单位为米

$$ATS(r) = \frac{J_{mean}(r) \cdot R_{mean}(r)}{R_{max}(r)}$$

ATS 的物理意义：将山体的综合视觉压迫感等效为一根垂直立于平地的柱体高度，单位为米。

### 第四阶：等效地形尺度

| 指标 | 公式 | 物理意义 |
|------|---------|---------|
| 等效突出半径 $R_{prominence}$ | $\arg\max_r J_{mean}(r)$ | mean_jut 达到峰值时对应的采样半径，反映山体突出形态的特征尺度 |
| 等效基座半径 $R_{base}$ | $\arg\max_r ATS(r)$ | ATS 达到峰值时对应的采样半径，反映山体综合地形锐度的特征尺度 |


### 补充指标：ORS（Omnidirectional Relief and Steepness）

ORS 的理论基础来自 Earl 与 Metzler 提出的全向高差-坡度泛函。其核心思想是：对参考点周围所有方向上的样点，计算相对高度差与距离构成的坡度项，并通过特定角度归一化核函数进行积分，最终得到一个具有长度量纲的综合陡峻度指标。

在理论上，ORS 可以写成对整个平面样点的积分形式：

$$ORS_f(p,h_0;h)=\left[\iint_{\mathbb{R}^2} f^2\!\left(\frac{h_0-h(x)}{r}\right) dA(x)\right]^{1/2}$$

其中 $r=\|x-p\|$，当 $u=(h_0-h(x))/r$ 小于等于 0 时，核函数贡献记为 0。原始论文进一步采用角度归一化核函数，使 ORS 在圆锥模型上满足良好的尺度协变和物理解释。该指标本质上是对“高差 × 坡度”信息的全方向综合。

## ORS 的工程化简化实现

### 为什么需要简化

原始 ORS 的严格定义是连续平面上的积分。若直接在高分辨率 DEM 上对每座山峰、每个采样半径、所有像元执行完整积分，计算量会非常大；当研究区域扩展到多个大区、并需要批量处理数千座峰时，GEE 任务数量、运行时间与导出体量都会迅速膨胀。因此，本项目没有在前端或批量预处理脚本中直接采用“全像元精确积分”方案，而是使用一套可控、稳定、可批量导出的近似计算流程来替代。

### 本项目在GEE脚本中采用的简化逻辑

1. **环带离散化替代连续积分**  
   将 0–10 km 范围拆分为 48 个同心环带：125–2000 m 每 125 m 一个环带，2250–10000 m 每 250 m 一个环带。这样可以把连续平面积分转成分环累计问题。

2. **确定性分层采样替代全像元遍历**  
   每个环带不对全部 DEM 像元逐一积分，而是采用固定的极坐标分层采样结构：
   - 径向分层数 `N_RADIAL = 5`
   - 角向分层数 `N_ANGULAR = 20`
   - 每环固定样本数 `SAMPLES_PER_RING = 100`

3. **按环带面积赋权**  
   每个样点不直接代表单个 DEM 像元，而是代表该环带面积的等份权重：

   $$w = \frac{A_{ring}}{N_{samples}}$$

   通过 `kernel_sq × point_weight_m2` 累计各样点贡献，再得到环带 ORS² 增量与累计 ORS 值。

4. **固定投影到局部米制坐标系**  
   为避免经纬度坐标下距离失真，脚本先将峰点与样点投影到 UTM 米制坐标系，再进行环带构造与距离计算。

5. **峰顶高程用局部 buffer 最大值修正**  
   若开启 `usePeakBufferMax = true`，则不直接使用峰点单像元高程，而是在峰点附近小缓冲区内提取最大值作为峰顶高程，以减轻 DEM 像元错位或落点偏移带来的误差。

6. **中心奇异保护**  
   在 $r \to 0$ 附近设定最小距离阈值 `minDistanceEps = 1.0`，防止坡度项分母过小导致数值爆炸。

7. **不做“高于峰顶区域掩膜”**  
   当前修订版显式取消了“高于峰顶区域掩膜”，保留所有有效 DEM 样点进入采样。随后通过原始 ORS 核函数中的 `u.max(0)` 逻辑，让高于参考点的地形自动贡献 0，而不是预先掩膜剔除。

8. **批量导出**  
   由于单任务峰点过多会造成 GEE 任务过重，脚本采用 `BATCH_SIZE = 500` 的批导出方式，把大区域峰点表拆分为若干导出任务。

### 这种简化的含义

这意味着本项目中的 ORS 更适合被理解为：

- **面向区域大样本比较的离散近似 ORS**
- **适合排序、分段分析和前端可视化的工程化版本**
- **与原始连续积分定义同源，但并非逐像元高精度复刻**

因此，前端展示的 `10kmORS`、`ORS 最大排名`、`ORS 各距离段击败率` 等字段，主要用于：

- 跨山峰比较
- 多距离尺度趋势判断
- 与 Relief / Jut / ATS 的互补对照

而不宜被理解为“严格数学意义下的精确连续积分真值”。

## 综合击败率指标

当前版本中，每座山峰在库内的**综合击败率**定义为以下六项击败率的平均值：

| 指标 | 字段 | 含义 |
|------|------|------|
| 高差均值击败率 | `mean_relief_crp` | mean_relief 在所有采样半径下的均值排名 |
| Jut均值击败率 | `mean_jut_crp` | mean_jut 在所有采样半径下的均值排名 |
| ATS均值击败率 | `mean_ats_crp` | ATS 在所有采样半径下的均值排名 |
| 10kmORS击败率 | `ors_10km_crp` | 10 km 半径累计 ORS 的库内排名 |
| 最大Jut峰值击败率 | `max_jut_crp` | max_jut 在所有采样半径下的最大值排名 |
| 最大ATS峰值击败率 | `max_ats_crp` | ATS 在所有采样半径下的最大值排名 |

击败率 = 1 − 排名百分位，越高越优秀（0% 为最差，100% 为最优）。

这一设计意味着综合排名不再只依赖传统的 Relief / Jut / ATS 三类指标，而是把 ORS 也纳入库内总体表现评价中，从而增强对“大尺度全方向陡峻感”的刻画。

## 距离段定义

每个距离段对应一组采样半径，段内排名取该范围所有半径下指标均值的库内百分位：

| 距离段 | 采样半径范围 |
|------|-----------|
| 极短距离 | 125 m – 500 m |
| 短距离 | 625 m – 1,250 m |
| 中短距离 | 1,375 m – 2,000 m |
| 中距离 | 2,250 m – 3,500 m |
| 中长距离 | 3,750 m – 5,000 m |
| 长距离 | 5,250 m – 7,000 m |
| 超长距离 | 7,250 m – 10,000 m |

在当前前端中，距离段筛选支持：
- 高差（Relief）
- Jut
- ATS
- ORS

其中 ORS 的距离段表现来自对应半径范围内 ORS 剖面值的分段排名或击败率统计。

## 地图功能

- **多库叠加显示**：可独立开关各数据库图层
- **山峰点击弹窗**：显示海拔、综合击败率、10kmORS、ORS 最佳排名及对应半径、最大 Jut / ATS 峰值、等效半径等摘要指标
- **多维筛选**：支持按高差均值、Jut均值、ATS均值、10kmORS、最大Jut峰值、最大ATS峰值等总体表现进行筛除
- **距离段筛选**：按七个距离段对 Relief / Jut / ATS / ORS 分别筛选
- **剖面折线图**：展示高差 / Jut / ATS / ORS 随半径变化的曲线及对应排名变化
- **总述图表**：支持查看全局指标与分段指标的跨库分布对比
- **等效半径圆**：可视化每座山峰的等效突出半径与等效基座半径范围
- **山峰检索**：支持按名称模糊搜索定位
- **3D 地形**：基于 MapTiler 地形数据的三维山体渲染

## 数据处理与前端逻辑说明

### 后处理脚本

GeoJSON 生成脚本会把各类 CSV 汇总为前端可直接读取的 GeoJSON / JSON 文件，包括：

- 山峰主点属性
- 多半径 Relief / Jut / ATS / ORS 剖面
- 库内总体击败率
- 各距离段击败率
- 最大值及其对应半径
- 等效突出半径 / 等效基座半径

### 前端中的简化与重组

由于前端强调交互速度与多库叠加能力，因此并不会在浏览器端重新对原始 DEM 进行 ORS 数值积分，而是直接读取预处理后的结果，并进一步进行：

- 距离段聚合
- 多指标联动筛选
- 弹窗摘要指标重组
- 折线图与排名图绘制
- 总述图表统计

因此，本项目的前端逻辑是“**以预处理结果为基础的展示与筛选层**”，不是 ORS 的原始数值计算层；原始或近原始数值计算主要发生在 GEE 与 Python 预处理阶段。
